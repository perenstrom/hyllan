Taking stock

PER-265 — throwaway prototype, not production code

Question this demo tests: stock-to-shelf and shelf-to-stock are two separate, independently-started flows for a Location — not two phases of one pass. Stock-to-shelf is a full-size, one-item-at-a-time walkthrough of every pantry item currently nonzero at the Location, alphabetical by name — editing a field sets an absolute value and saves immediately, leaving it unchanged is an implicit confirmation. Shelf-to-stock is a standalone lookup: pick any existing pantry item in the household — whether or not it's currently tracked at this Location — see its current quantity here, and adjust it. Both are stateless: closing either at any point ends it immediately; edits already made are already saved; nothing forces reaching the end.

Grounded in ADR 0006 and CONTEXT.md: a correction never touches that item's rows at other Locations, and never creates a new pantry item.
