# App skeleton: Next.js App Router, Vitest, Tailwind, npm, Node 24

The previous bare `ts-node` skeleton is replaced entirely with a Next.js (App Router) app under `src/app`, built with npm and pinned to Node 24 (current LTS) via `.nvmrc` and `engines.node`. We chose App Router over Pages Router since it's the actively developed router and the default for new Next.js apps. Styling uses Tailwind CSS, included from the start since it's a common baseline rather than a later migration. Linting is `eslint-config-next` (flat config) only — no extra `typescript-eslint` strictness or import-ordering rules yet, since those are easy to add once real code exists to check. Formatting is Prettier, wired into ESLint only via `eslint-config-prettier` (which turns off ESLint's stylistic rules) rather than running Prettier as an ESLint rule, keeping linting and formatting as two independent, non-conflicting commands. Testing is Vitest, configured upfront for both plain unit tests and React component tests (jsdom environment + React Testing Library), since retrofitting a test environment after components exist is more disruptive than including it now; tests are co-located with source as `*.test.ts`/`*.test.tsx`. We skipped pre-commit hooks (Husky/lint-staged) for now — CI (a GitHub Actions workflow running lint, typecheck, test, and build) catches regressions without adding local commit friction. TypeScript uses Next.js's default `strict: true` with no additional compiler flags, and a `@/*` import alias resolves to `src/*`. `tsconfig.json` strictness and ESLint rule strictness are both treated as easy-to-raise-later floors, not final settings.
