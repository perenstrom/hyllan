# Households are single-user, auto-created at signup, and cascade-delete with the account

Signing up automatically creates a household for the new user — there is no separate "create or join a household" step. A household is strictly single-user for MVP: no invite links, no join flow, and no path for a second person to become a member. We kept household as a distinct entity from the user account (rather than hanging pantry items directly off the user) purely so the domain language and schema don't need renaming if shared, multi-member households are introduced later; the cost today is one extra table and a `household_id` foreign key on pantry items instead of a `user_id`. Deleting a user's account cascade-deletes their household and all its pantry items immediately — we considered a soft-delete/grace-period window to allow account recovery, but rejected it since there is no second household member who could be surprised by the data disappearing, and it adds a cleanup job for no MVP benefit. A household has no name field: since it is never shared or distinguished from its single owner, the UI just refers to "your pantry" rather than a household name.
